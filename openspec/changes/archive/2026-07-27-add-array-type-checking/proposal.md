## Why

配列式と `for` は実行できる一方、型検査ではどちらも型が分からないものとして扱われるため、正典プログラムの `self.users` やループ変数 `u` に対する誤りを実行前に検出できない。次の型検査の一歩として配列の要素型を明示し、既存の式・フィールド検査へ接続する。

## What Changes

- 型注釈に `[T]` と `[T]?` を追加し、配列の要素型と配列自体の optional 性を表せるようにする
- 空でない配列リテラルの全要素が同じ型であることを検査し、配列型を推論する
- 空配列リテラルは、struct field、関数引数、戻り値、代入など期待される配列型がある位置でだけ適合させる
- `for x in xs` の反復対象が配列であることを検査し、`x` をその要素型で束縛する
- 配列型を既存の引数、戻り値、field、代入、optional の照合へ流す
- 正典プログラムの未宣言な `Users` 型を `[User]` に置き換える
- メソッド候補の解決、trait と impl の署名照合、配列の可変性・所有権は対象外とする

## Capabilities

### New Capabilities

- `array-type-checking`: 配列型の構文、配列リテラルの型付け、空配列の文脈的照合、`for` の要素型束縛を規定する

### Modified Capabilities

なし。

## Impact

`src/ast.rs` の型表現、`src/parse.rs` の型構文、`src/module.rs` の型名解決、`src/typecheck.rs` の型表現・推論・照合、正典プログラム、文法ドキュメント、関連テストが影響を受ける。新しい外部依存は追加しない。
