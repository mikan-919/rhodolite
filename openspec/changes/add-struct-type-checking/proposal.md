## Why

`struct` 宣言はフィールドを記録しているが、現在の処理系は生成時にその宣言を照合せず、欠落・余分・重複したフィールドや、フィールドを持つ型の裸の名前を実行時の値として受け入れる。型検査へ進む最初の一歩として、まず宣言済みの struct の「形」を静的に保証する。

## What Changes

- モジュール解決後のプログラムに対して、struct 宣言と struct 生成の整合性を実行前に検査する。
- struct 生成では、型が宣言済みであり、宣言された全フィールドを過不足なく一度ずつ指定することを要求する。
- struct 宣言自身の重複フィールドをエラーにする。
- 裸の struct 名を値として使えるのは、フィールド0個の struct だけに限定する。
- フィールド値の型、関数の引数・戻り値、演算、optional、配列の型検査はこの変更に含めず、whole-program 型検査の後続段階に残す。

## Capabilities

### New Capabilities

- `struct-shape-checking`: struct 宣言と生成式のフィールド集合を静的に照合し、不正な struct 値が評価へ到達しないことを規定する。

### Modified Capabilities

なし。

## Impact

- モジュール解決済み AST を検査する新しい意味解析段階と、その CLI 診断が加わる。
- `src/main.rs` の処理順、struct 情報の収集、式木の走査、および関連テストが影響を受ける。
- これまで実行時に受理されていた不完全・過剰な struct 生成は静的エラーになる。
- 外部依存関係の追加は予定しない。
