# 所有データの内部並びと、直列化する Rhodolite ABI v1

Wasm の成果物が `str`・struct・enum・optional・配列を運べるようにするにあたり、
**線形メモリ上の並び**・**import を1つも持たない所有権ランタイム**・**ホスト境界の
表現**の3つを決める。

[ADR-0009](./0009-core-wasm-is-the-compiler-artifact.md) が置いた「成果物は
import-free な Core Wasm と埋め込み JSON」という骨格はそのまま。差し替えるのは
その決定6が引いた **v0 = scalar だけ** という線と、境界表現が scalar に閉じている
という前提だけである。[ADR-0010](./0010-owned-values-and-inferred-borrows.md) の
所有・借用・`indirect` の意味論も変えない。ここで決めるのは、その意味論を
32bit の線形メモリへどう落とすか。

## Decision

### 1. 内部の並びはコンパイラの都合であって契約ではない

型 → 並びは検査済み HIR と宣言 ID の決定的な関数とする。同じ入力からは同じ
offset が出るが、**その offset をホストへ公開しない**。オフセット・容量・
allocator のヘッダ・glue の関数番号は、どれもメタデータに出さない。

こうしておけば、後から詰め方を変えても ABI の版を上げずに済む。ホストが内部の
ポインタを直に触れる案は却下した。並びが永久に固定されるうえ、壊れた別名
グラフが単独所有を破れてしまう。

並びは次のとおり。オフセットも大きさも 32bit 符号なしで、計算はより広い幅で
検査する。揃えは2の冪で 8 を超えない。アドレス 0 は「無効・未初期化」に予約する。

| 型 | 記憶の形 |
|---|---|
| `bool` / `int` / payload なし enum | 1 / 8 / 4 byte |
| optional | `{u8 tag, 詰め物, payload}`。tag 0 が空、1 が有り |
| struct | 宣言順にフィールドを直に並べる |
| payload 付き enum | `{u32 variant, 詰め物, 最大の payload}` |
| `str` | `{u32 data, u32 len, u32 capacity}` + 別割り当ての UTF-8 bytes |
| `[T]` | `{u32 data, u32 len, u32 capacity}` + 刻み幅で並ぶ要素 |
| `indirect` なフィールド/payload | 子アドレス `u32` 1つ |

`indirect` だけが再帰の層を切る。だから再帰型でも根の大きさは有限に決まる。
入れ子のフィールドを全部独立したポインタにする案は却下した。ソースが
`indirect` で言い分けている区別が消え、割り当てが無用に増える。

### 2. 実行時の値は Copy なら平ら、所有と借用ならアドレス

内部の呼び出し規約は検査済みの型から決まる。`unit` は値を持たず、`bool` は 0/1 の
`i32`、`int` は `i64`、payload なし enum は宣言順のタグ `i32`、Copy の optional は
タグ `i32` と平らにした payload。所有する非 Copy 値と `&T` / `&mut T` は、どちらも
非 0 の `i32` アドレス1つになる。

移動はアドレスを写して元の初期化フラグを落とすだけ。借用は所有を取らずに
アドレスを写すだけ。すべてを `i32` の箱にする案は却下した。`int?` のような Copy の
optional まで割り当てを共有するか、隠れた参照カウントを持つことになる。

### 3. allocator は自前で書き、生成モジュールへ埋め込む

ABI の受け渡し領域と静的データが決定的な前置きを占め、その後ろに揃えた heap が
続く。heap のブロックは大きさと空きリンクを持つ固定ヘッダを備え、空きリストは
アドレス順、選択は first-fit、分割は残りが正しいブロックになるときだけ、解放は
アドレス順に挿して隣接を併合する。入らなければ必要な最小ページ数だけ
`memory.grow` して再試行し、算術のあふれと成長の失敗は trap する。

bump allocator は却下した。有界なループの中で普通に drop しても、メモリが
増え続けて OOM になる。`dlmalloc` や WASI を持ち込む案も却下した。所有権の説明が
この処理系の主題であり、成果物は import を持たないと決めてある。

### 4. clone・等値・drop は並びごとに生成した関数へ寄せる

到達した並びごとに `drop_T` / `clone_T` / `eq_T` を1つずつ生成し、構造的な鍵で
共有する。再帰する glue は子を訪ねる前に関数番号を予約して輪を閉じる
([ADR-0008](./0008-ambient-abi-is-a-specialization-plan.md) の特殊化と同じ手)。
`drop_T` は活きている中身だけを辿って解放し、`clone_T` は新しい根を割り当てて
深く写す。Copy の子は素直な load/store で足り、所有の glue は要らない。

式のたびに glue を展開する案は却下した。同じ処理が重複し、再帰型が書けない。
実行時の型記述子を解釈する案も却下した。生成モジュールの中に2つ目の型システムが
生えてしまう。

### 5. 掃除は検査済みの所有権計画から下ろす

各 CFG エッジの drop 計画を作るのは所有権検査だけとし、backend はそれを読むだけに
する。非 Copy の所有ローカルはアドレスの席と `i32` の初期化フラグを持ち、
`Drop::Local` はフラグで守った `drop_T` になる。`return` は結果を退避してから
計画順の掃除を通す1つの出口へ寄せる。`unreachable` の trap は掃除を通らない。

backend が字面のスコープから掃除の順を組み直す案は却下した。移動と合流の答えは
所有権検査がすでに出しており、2箇所で解くと必ずずれる。

### 6. 公開境界は直列化した ABI v1。scalar だけの面は v0 のまま

公開署名がすべて scalar ならモジュールは ABI v0 を選び、既存のラッパも
メタデータもそのまま。公開面に所有する型が1つでも出たら、モジュール全体が
ABI v1 になる。

v1 は豊かな引数を `(i32 ptr, i32 len)` へ、豊かな戻り値を `(i32 ptr, i32 len)` の
2結果へ平らにする。モジュールは `memory` と `__rhodolite_abi_reserve(i32) -> i32` を
export し、ホストは**最後に予約した**受け渡し領域へ正準 bytes を置く。ラッパは
本体へ入る前に境界を検査して新しい所有へ復号し、結果は符号化してから内部の
所有者を drop する。返った bytes は次の予約か次の export 呼び出しまでしか有効でない。

符号化は宣言の型で自己完結する。`i64` はリトルエンディアン、Boolean は1 byte、
`unit` は 0 byte、`str` は `u32 byte_len + bytes`、struct は宣言順、enum は
`u32 tag + 活きた payload`、optional は `u8 tag + 有ればその中身`、配列は
`u32 要素数 + 要素`。復号はあふれ・不正なタグ/Boolean/UTF-8・途中切れ・余りを
本体の実行前に拒否する。

内部の heap ポインタを直に渡す案は決定1の理由で却下した。JSON は却下した。
数と文字の曖昧さとパーサの大きさに見合う価値が、型の付いた2進境界には無い。
Component の Canonical ABI と WIT は今回も見送った。必要になった下流の
フレームワークが、この bytes を包めばよい。

### 7. メタデータは公開署名から辿れる型グラフだけを載せる

ABI v1 のメタデータは `version` / `entry` / 名前順の `exports` に続けて `types` を
持つ。公開署名の型は scalar の綴りか、決定的な `t0`, `t1`, ... の参照になる。
型グラフは entry、続いて公開名の昇順で辿り、宣言の中はフィールド/variant/payload の
順。子を訪ねる前に ID を予約するので、再帰する `indirect` 型も閉じる。

**公開署名から到達した型だけ**を載せる。読み込んだ全部を載せる案は却下した。
非公開の宣言はホストとの契約ではなく、無関係な編集がメタデータを動かしてしまう。

## Consequences

- 生成モジュールは自前の allocator と glue を抱えるので、scalar だけのときより
  ずっと大きくなる。scalar のみの出力は従来どおりのバイト列に留める
- 内部の並びを後から変えても、ホストの契約は ABI v1 の bytes のままでいられる
- 手書きの allocator は破壊的なバグを持ちうる。private に閉じ、独立エンジンでの
  割り当て・解放のストレスを常時回す
- `memory` を export する以上、敵対的なホストはモジュールの状態を書ける。ホストが
  書いてよいのは最後に予約した領域だけであり、入力は毎回検証する。完全な分離には
  multi-memory か component 境界が要り、この Core Wasm の ABI の外側にある
- trait・ambient・メソッドの生成は引き続き未対応。次の change がそこを埋める
