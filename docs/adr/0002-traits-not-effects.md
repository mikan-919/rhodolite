# `effect` を廃し trait に一本化する。ambient の記述は3箇所に限る

`effect Db { fn find(...) }` と `trait Db { fn find(...) }` は字面がほぼ同一で、
両方持つと「関数の集まりを宣言する構文」が言語に2つできる。違いは宣言側ではなく
使用側(推移するか・推論されるか)にしかないため、宣言構文を2つ持つ理由がない。
よって **`effect` キーワードを廃止し、「ambient に置かれた trait」をエフェクトと定義する**。

その上で、ambient に関わる記述をソース上の4箇所に限定する:

| 位置 | 書くもの |
|---|---|
| 契約 | `trait Database { fn save(u: User -> unit) }` |
| スロット宣言 | `effect db: Database` |
| 提供 | `db(Postgres::new(url)): { handle() }` |
| 使用 | `db.save(u)` |

**この4箇所以外には1文字も現れない。**経由するだけの関数は無記述で、関数が何を要求
するかは推論する(書かない)。IDE がゴーストテキストで `@env db, clock` として見せる。

## 追記(同日): `effect` はスロット宣言として復活した

`effect` キーワードは廃止しない。ただし**関数を1つも宣言しない**形で入れる:

```rhodolite
trait  Database { fn find(...)  fn save(...) }   // 関数の集まり = 契約
effect db: Database                              // Database 型のスロットが1つ、名は db
```

このADRが禁じたのは「関数の集まりを宣言する構文が2つある」ことであり、
`effect db: Database` はそれに当たらない。**契約(trait)と役割(スロット)を分けて書く**形。

差し引きで**規則は減っている**:

- **得**: ambient になれる trait が宣言で決まる(`Display` を ambient 位置に置けない)/
  スロットが常に名前を持つので同じ trait の複数実装で曖昧性が構造的に発生しない /
  役割名(`db`, `clock`, `primary`, `replica`)がインターフェース名より呼び出しで読みやすい
- **消えたもの**: `@Replica` のシジル、「ambient が1つなら省略・2つ以上なら名指し必須」
  という特例規則
- **代償**: 宣言形が1つ増える。`db.save(u)` はローカル変数と見た目が同じになる
  (ただしレシーバが見えており、`effect db: Database` がモジュール先頭にあるため追跡可能。
  裸呼び出し `save()` とは別物)

## Considered Options

- **ハンドラを関数のレコード値にする**(`Db { find = fn(..){..} }`)。v1 の実装は最小に
  なるが、将来 trait を入れた時点で二重化問題が戻る。
- **要求をシグネチャに書かせる**(`@env Database, Clock` 必須)。公開境界の互換破壊と
  エラーの遠隔作用が消え実装も軽いが、`Database::save()` と同じ情報の二重管理になる。
  呼び出しが `Trait::` で修飾されている時点で可読性は達成されているため不採用。
  将来ライブラリをバイナリ配布する必要が出たら再検討する。
- **裸呼び出し**(`save()`)。「何も書かない」が最も鋭くなり Koka もこの形だが、
  `find`/`save`/`now`/`log` は普通の関数名として頻出するため衝突規則の設計が必要になり、
  かつ呼び出し行を読んでもエフェクトだと判別できない。不採用。

## Consequences

- 提供構文 `Database(db): { ... }` は syntax_design.md の `Head ':' block` 産出そのもの。
  文法は4産出のまま増えず、将来のアロケータ前置 `ar: expr` と同じ棚に乗る。
  Head が宣言する4項目に `ambient の変更` が既に含まれていた(2026-07-13)ため、
  エフェクト柱は構文柱に後付けなしで接続する。
- v1 に trait 解決・impl 探索・構造体が入る。レコード案なら省けていた分量。
- 同じ trait を複数同時に置く場合のみ `@Replica` でスロットを名指す。
  規則は「曖昧なら名指せ」の1本で、単一の場合の記述量はゼロ。
