# v1 のスコープをエフェクト1本に絞り、所有権の柱を棚上げする

> **歴史的判断。** v1 完了後、所有権・借用・寿命推論は後続実装として
> [ADR-0010](./0010-owned-values-and-inferred-borrows.md) で採用された。この ADR の
> 「実装しない」は当時の v1 スコープを指す。

Rhodolite には当初3本の柱があった — 構文(Head=環境構築子)、メモリ(Rust の所有権から
`'a` だけを消す)、エフェクト(DIコンテナの死)。v1 では**エフェクトだけを実装し、
所有権・借用・ライフタイム推論は実装しない**。設計文書は将来構想として残す。

理由は3つ。**(1) 顧客が別人だった。**「`'a` に殴られている人」はシステム系、
「DIコンテナと戦っている人」はバックエンドアプリ系で、同一人物ではない。
**(2) 所有権は丸ごと山場。** rustc へ委譲しても浮くのは検査器だけで推論器は自作になり
(rustc はシグネチャのライフタイムを推論しない)、それがこの柱の全体だった。
**(3) 前作 iris で一周済み。** 二周目には「なぜまた同じことを」への答えが要るが、
エフェクト推論の方が新規性も説明のしやすさも上。

## Consequences

- **tail-resumptive 限定の根拠が変わった。** 「所有権を持つ言語では複数回再開が
  アフィン型と衝突するので自動的に導かれる」という論拠は、所有権を外した時点で失効した。
  結論は変わらないが、現在の根拠は「継続キャプチャの実装が丸ごと不要になり実装が軽い」
  という工学的なものに格下げされている。面接等で理由を問われたら後者で答えること。
- **2本の柱は直交していなかった。** effect_design.md は「エフェクト柱はメモリモデルと
  直交」と書いていたが、これは誤り。iris のソースでライフタイム `'a` を持つ struct は
  6個あり、うち4個(`FnCodegen<'a>` 26フィールド、`Checker<'a>` 21フィールド、
  `Flow<'a>`、`Borrows<'a>`)が**依存を持ち回るためだけの容れ物**だった。
  `FnCodegen` は26フィールド中16個が `&'a` の借用入力。つまり iris で `'a` を
  書かされた主因は依存の配線であり、2本の柱は同じ病気の2症状。
  棚上げした所有権の柱は、エフェクトを入れた分だけ後から軽くなる。
- 副作用として、26フィールドのコンテキスト struct が生む二次被害
  (全処理をそのメソッドにするしかなくなり、codegen.rs 4,297行 + typeck.rs 2,948行 =
  iris 全体の54%が2ファイルに集中した)も、ambient 束縛があれば回避できる見込み。
